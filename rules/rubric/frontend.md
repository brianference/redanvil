# Frontend lane (v1.1.0)

- fe-theme-tokens-only (blocker, det): every value from theme tokens; no hardcoded hex or px; overlays via alpha() against an existing token.
- fe-a11y-contrast (blocker, visual): WCAG AA contrast — 4.5:1 normal text, 3:1 large text and UI boundaries. Measured on the rendered page and recorded with evidence; it cannot be decided statically, and declaring it `det` while no check existed let it pass unmeasured.
- fe-favicon-legible (blocker, det): the favicon must read at 32x32 — ink coverage in a sane band, mean Sobel detail energy above a floor, and mean ink contrast against white and dark tab chrome. fe-brand-mark only checks bytes and shape; a full-size logo that smudges at tab size passes it.
- fe-brand-mark-size (blocker, det): the header brand mark (img or svg) must render at ≥ 48px height at viewport 1280 and ≥ 32px at 375. fe-brand-mark checks bytes and shape; a real asset still shipped at 32px and looked like a smudge. Fail when no image/SVG mark is found in the header.
- fe-breadcrumbs (blocker, det): every non-home inner/detail route has a `nav` whose accessible name matches /breadcrumb/i and contains a link back toward the parent. n/a only for single-route apps. Premium-nav prose required breadcrumbs; nothing measured them.
- fe-result-in-viewport (blocker, det): after typing a known-narrowing query into search, something that changed must sit inside the first viewport at 375 and 1280. Fail with the measured y of the nearest changed element ("your result is 1042px below the fold"). n/a when the app has no search. fe-search-present and fe-visible-response both missed a result at y=1942 in a 900px viewport.
- fe-resource-links (blocker, det): every item detail route carries at least one external link (different host) that resolves to 2xx or 3xx when fetched with a browser user-agent. Cache by URL within a run; name each dead link with status and page. n/a only when the app has no item detail route. Invented guide URLs are the anti-hallucination failure in its worst form.
- fe-legal-substance (blocker, det): Terms and Privacy both meet the reference standard (≥ 1400 words, ≥ 14 h2 sections) and cover the required topics (acceptance, liability, indemnity, governing law, contact; collection, retention, rights, children, security, etc.). Word floors alone are not enough — report every missing topic by name.
- fe-structured-data (blocker, det): home declares valid `application/ld+json` with `@context` and `@type`, and a `<link rel="canonical">` with an absolute http(s) URL. per-app-pack already required JSON-LD; this measures it.
- u-legal-claims-true (blocker, det): bidirectional comparison of legal/privacy copy against code for cookies, accounts/auth, payments, third-party analytics/tracking, and email collection. Copy that denies what the code does (or code that does what copy never discloses) fails.
- fe-i18n-central-copy (blocker, det): all user-facing copy in the central locale bundle, namespaced by feature; never hardcoded inline.
- fe-no-unsanitized-html (blocker, det): no dangerouslySetInnerHTML without a sanitizer.
- fe-pages-compose (major, judge): a page's return reads as a short list of named components; the page owns state and passes it down.
- fe-fail-closed-states (major, det+judge): every screen defines explicit loading, error, empty, and partial states; a failure never renders as a clean empty success.

## Premium/design rules (method `visual`, fail-closed)

These are scored from a recorded visual review of the rendered page, never from code.
Method `visual` is **fail-closed**: with no recorded verdict the rule FAILS, so a run
cannot score above zero until a real visual review at 375 / 768 / 1280 is recorded.
This is the root-cause fix for premium requirements that used to auto-pass because
nothing in the scored rubric decided them.

- fe-light-dark (blocker, det): light AND dark mode must change what is PAINTED, not only a data-theme attribute. Samples the computed background of landmark regions (header, each top-level section/main child, footer) in both themes and FAILS when any region's background is effectively unchanged. Colours are converted via the browser canvas — never hand-parsed. Attribute-only checks shipped a light page whose hero stayed black on hardcoded dark tokens. Known-answer fixtures: hardcoded-hero FAILS; fully tokenised PASSES.
- fe-premium-nav (blocker, visual): a polished sticky top nav with the brand mark and primary links that have clear hover AND active states (not bare text links); overflow in a menu; breadcrumbs on inner/detail pages.
- fe-required-pages (blocker, visual): Home, About, Terms, Privacy, and Contact all present and reachable from the shared nav/footer.
- fe-no-attribution (blocker, visual): no "made with" / "built with" attribution text anywhere in the UI.
- fe-responsive-375 (blocker, visual): no overlapping or clipped text at 375px; verified at 375 / 768 / 1280. Also measures `input`/`textarea` placeholder text width (canvas measureText with the computed font) against the field's content box -- placeholder is an attribute, not textContent, so the old check missed "Find a crop by nar" truncated at 375.
- fe-product-completeness (blocker, visual): the app delivers its stated core feature end-to-end with usable output; a flow that collects input but produces nothing fails.
- fe-visual-review-recorded (blocker, visual): a visual review was actually performed and recorded — screenshots at all three breakpoints in both themes, zero console errors. The meta-rule that cannot auto-pass.
- fe-design-archetype (major, visual): the app is built as the layout archetype §7.3a named for it, and has not fallen back to a shell that section explicitly rejects. The direction was always computed as structure -- `chooseDesignDirection` returns the archetype, the visual direction, and the shells to avoid -- then rendered to prose and discarded, so a section calling itself BINDING was enforced by hope. What is measured is the anti-pattern the spec names in its own words: a generic centred column under a sticky header. That is detectable; "is this a Split workbench" is not, and a check that guessed would be worse than none.
- fe-cold-visitor (blocker, visual): a first-time visitor gets a working app. Observed with NOTHING forced -- no data-theme set, no localStorage, no seeded route, only an emulated OS preference -- the resolved theme matches the system at both settings, the primary flow produces a real result for an input nobody seeded, and the console is clean. Every other check sets up the state it then measures: the accessibility audit assigns data-theme before it looks, the design audit exercised only the theme TOGGLE, the control audit crawls seeded routes. Each is right for its own purpose and together they left one hole, through which quickflight shipped a light theme to every visitor whose OS asked for dark and a search that answered an empty list for almost any route a person typed. Both were found by a human looking at the site.
- fe-seo-og (major, visual): per-route title/description, Open Graph tags, a real OG image, sitemap, robots.txt, JSON-LD, semantic headings.
- fe-cross-link (major, visual): sibling apps in one system cross-link in a shared header/footer so the product is navigable, not orphan pages.

## Measurable mobile-ux rules (method `visual`, from mobile-design-rules R1–R12)

Promoted from prose/checklist to scored rules so the mobile design system is measured, not just documented.

- fe-touch-targets (blocker, visual): primary tap targets >= 44x44 pt / 48x48 dp; >= 8pt between adjacent controls (R1.1/R1.2).
- fe-type-floor (blocker, visual): body text >= 16px on mobile for primary content (R3.1).
- fe-noncolor-state (major, visual): state is never signalled by color alone; pair with icon/text/weight (R4.2).
- fe-safe-areas (major, visual): respect top/bottom/landscape safe areas; content never trapped under fixed header/tab bar (R2.1/R2.2).
- fe-seo-assets (major, det): public/ ships sitemap.xml, robots.txt, and a real OG image. These are files — measured, not asserted.
- fe-icon-button-labels (blocker, det): every button whose children carry no text has aria-label or aria-labelledby (design rule R1.5).
- fe-desktop-width (blocker, visual): every route's PAINTED content — not its container — occupies at least 80% of the viewport at 1440 and 1920. Measured on the rendered page by `.github/scripts/desktop_width.mjs`; a passing verdict must cite its report. Measure what is drawn, never a block element's box: a `<div>` or `<h1>` is 100% wide by default, so measuring the container reported 93% for a page whose content sat in the left third. A rem cap cannot hold a percentage promise — use a percentage on the container and protect the line measure with column counts, never by starving the container. Column counts must follow the content (a quantity query), or a page with two sections leaves an empty third column.
- fe-no-inline-width (blocker, det): no `width` / `maxWidth` / `minWidth` layout cap in an inline style object or `style={{...}}` prop. Width belongs in a CSS class where a media query can lift it. An inline style beats a class, so an inline cap is unliftable by definition — this shipped four separate times here (template gallery, saved PRD, wizard form, saved page) and each time it held a desktop layout to a third of the screen while every other check passed. `width: '100%'` and `maxWidth: '100%'` are allowed: they cap nothing.
- u-no-placeholders (blocker, det): nothing user-visible may be a stand-in. No lorem, `TBD`, `FIXME`, "coming soon", `href="#"`, stand-in nouns, or generated page stubs. R32: a scaffold emitted `'<Name> page for <slug>.'` and four one-sentence legal pages shipped and passed every check, because a stub was that template's FINISHED output -- not an unfinished shortcut. A placeholder that renders as a plausible sentence is indistinguishable from real copy to everyone except the person who wrote the template. When real copy is impossible, emit something that FAILS a check and names the obligation. See R32.
- fe-visible-response (blocker, det): every action that changes the primary content must move the viewport or focus to the change, and a client-side router must reset scroll on route change. R34: pressing Search rendered its outcome at y=1341 in a 1000px viewport, so nothing visible changed and the button was reported as completely non-functional -- the "no flights match" notice was correct, specific, and 341px below the fold. A footer link kept the scroll position and landed the reader 1044px into a document they had never opened. Scroll AFTER the change renders, not in a promise callback: scrolling against the previous layout left an empty state at y=-128. Reserve the sticky header with scroll-margin-top. Tests must assert the viewport (toBeInViewport, or a boundingBox against innerHeight) -- toBeVisible() passes for an element far below the fold, which is why a green suite missed all of this. See R34.
- fe-search-present (blocker, det): every app with a browsable collection MUST have real TEXT search on the collection view — a text input whose accessible name matches /search|find/i (a bare `<select>` filter is NOT text search). The check drives the real deployed or served app with Playwright: count result rows, type a query that matches a known subset, count again, and FAIL when the count does not strictly decrease or the same rows remain. If a collection API reads or is called with q/search/query, that parameter must CHANGE the response body (an ignored `?q=` is a fail). A search box that renders and does nothing is worse than none. n/a ONLY when the app has no collection route at all.
- fe-assistant-present (blocker, det): every app MUST ship an AI assistant that answers questions about ITS OWN data: a chat affordance reachable from the shell, backed by a real endpoint (`functions/api/assistant.ts` or similar) that calls a model in the Worker (Cloudflare Workers AI by default) and grounds its answer in the app's own database rather than general knowledge. A stubbed or canned-response assistant FAILS. n/a ONLY when the app genuinely has no queryable domain data. An app that cannot answer a question about its own data makes the user do the reading.
- fe-brand-mark (blocker, det): the header brand mark must be a real raster or substantive vector asset the shell references — not a text span, not an emoji, not a single-glyph placeholder. Favicon and OG art must exist under public/ and must not be a trivially small hand-drawn stub (the failure class that shipped a literal "AZ" span and a 361-byte rect+text favicon while still clearing 90+). PASSES only when a real asset exists AND the shell references it.
- fe-prior-art (blocker, det): `SOURCES.md`, `INTEGRATIONS.md` and `COMPETITORS.md` must all exist at the app root, and none may still contain the scaffold/generator unwritten marker ("Fill this in.", template ellipses, `[UNWRITTEN]`). These are §7.3a / R23 / R29 / R31 blockers that lived only in prose, so an app could ship with none of the three files and still pass the scored gate. A missing file means the step did not run.
