# Loop-gate lane (shipping)

Operational shipping requirements scored against the app under gate. A clean score without a ship is not done.

- lg-shipped (blocker, det): an app is not finished until it is SHIPPED -- in a GitHub repo, pushed, deployed to a production URL, proven to be serving the scored commit, AND measured at the finish line. Why: builds cleared 90+ and then sat on a local disk with no remote and no URL, so "done" meant "the gate passed" rather than "a user can reach this build." Separately, repo+push+URL+hash alone let an unmeasured app be called shipped while the design audit never ran. All five must hold, fail closed: (1) git repo with `origin` pointing at a real GitHub URL; (2) HEAD is pushed (`git rev-list origin/<branch>..HEAD` empty); (3) production URL from `.redanvil/claims.json` `deployUrl` returns HTTP 200; (4) deployed `assets/index-<hash>.js` matches the newest local `dist/assets/index-*.js` (a wrangler success message is not proof); (5) the app's own gate result meets the finish line (`results/<slug>.json` with finalScore >= threshold and zero failing rules). Missing or sub-threshold results FAIL. N/A only with no wrangler.toml AND no deployUrl; wrangler present without a remote is FAIL, not n/a.
- lg-result-reproduces (blocker, det): a committed `results/<slug>.json` must recompute independently -- `computeScore` over the recorded per-rule outcomes equals `finalScore`, `provenance.commit` matches HEAD, and the rule id set invents nothing outside the rubric.
