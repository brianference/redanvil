# Testing lane (v1.0.0)

- u-test-presence (blocker, det): changed source files have tests; Storybook play() stories, Playwright specs, and axe specs count on the frontend.
- u-test-acceptance (blocker, det): the app has acceptance specs that drive the real UI in a browser, interact with controls, and assert on the OBSERVABLE RESULT — the rows a filter leaves, the value an input holds, the state a selection exposes — never on the control restyling itself. Unit tests over pure functions prove the functions are right, not that a user can reach them: a build once passed 12/12 design rules, zero axe violations and 49 unit tests while shipping a calendar that could not select a date range and a route that could not be changed, because the correct filter logic was never wired to a control. See R27.
- u-test-feature-audit (blocker, det): the app inventories its own interactive controls from the RUNNING page and fails on any control no test claims — `scripts/feature-audit.mjs` plus `tests/features.manifest.json`, wired into both `test:features` and `verify`. Acceptance tests prove the suite drives the UI; they cannot prove it covers the app, because the tests and the coverage claim come from the same mental model and a control nobody thought of is a control nobody tested. Three shipped that way out of a green repository: a Search button that produced no visible response, a public write endpoint, and an assistant that had answered 502 for two months. Every manifest entry must name a test that OPERATES the control and must resolve to a real spec file and a real test title; an unresolvable claim is fiction, and a `TODO` in the test field documents the gap instead of closing it.
- u-test-coverage-ratchet (major, det): overall line coverage never falls below the highest this app has recorded, and the bar itself cannot be edited down — the check reads every historical value of `highWaterPct` out of `.redanvil/coverage-state.json`'s git history and fails when the committed value is lower than one it previously held. A correctly-shaped state file is indistinguishable from a fabricated one, so the number alone proves nothing; lowering the bar to fit the result is the cheapest way to defeat a ratchet and looks exactly like an ordinary edit. Keep the file tracked: an ignored file has no history to check.
- u-api-real-output (blocker, det+judge): every route under `functions/api/**` is claimed by a realistic example in `tests/api-examples.json` and answers it with something real — the route inventory comes from the app on disk, so a new endpoint is unproven-by-default. The det half boots the app on the real Workers runtime and fails a non-2xx, an empty body, an empty collection under `nonEmpty`, fewer results than a declared `minItems`, or placeholder content in the response. The judge half reads the captured live traffic and decides whether those answers deliver what the product claims, which nothing static can. The control audit proved every button was clicked by a test and said nothing about what came back: QuickFlight passed contrast, touch targets, painted width, 49 unit tests, zero console errors and the control audit, while its assistant had answered 502 for two months and its catalog held two route/date pairs, so any route a person typed returned nothing.
- u-test-adequacy (major, det+judge): a new public field, branch, or behavior in the diff is referenced by at least one assertion in the diff's tests.
- u-test-behavioral (major, judge): tests assert behavior and error branches, not implementation details; mock at the boundary seam.
