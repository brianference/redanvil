## The main finding: seven checks that could not do their job

All were green since the day they were written. Each was found by RUNNING it,
never by reading it. Fixed in `9c17df9` and follow-ups.

| Check | What it got away with |
|---|---|
| `meas-two-run` | Counted one measurement written twice as "two runs agreed" (6 checks) |
| `meas-known-bad` | Returned pass on an unresolvable fixture path, so prose satisfied G1 |
| `meets_the_bar` | Called `isDone()` without four opts — C2, C10, F5, A6 were UNREACHABLE |
| `lg-shipped` cond 5 | Read its own prior failure back; could never self-clear |
| `lg-shipped` cond 2 | Required HEAD pushed, deadlocking the first push by construction |
| `lg-result-reproduces` | Required `provenance == HEAD`, unsatisfiable inside reverify; missing-rule branch was a no-op |
| `fe-assistant-present` | Accepted the bare word `filters` as proof of DB grounding |
| `fe-light-dark` | Read only `backgroundColor`, so a gradient hero false-FAILED |

**Three of these had a second floor under the first fix:**
- The two-run fix recorded both timestamps at write time, so a fast measurement
  produced byte-identical records — 4 of 6 failed the run meant to prove them fixed.
- `lg-shipped` cond 5's fix moved the circularity from the rules list to the
  stored `finalScore`, which a blocker failure pins at 0 forever.
- Excluding lg-shipped's *outcome* would have re-triggered it via
  `FAIL_CLOSED_METHODS`; the *rule* had to leave the rubric set.

**Fabricated provenance found:** the five `meas-*` checks never wrote a
`knownBad` field at all. The prose entries were hand-typed into a file whose
whole job is proving measurements are real. They now self-record a resolvable
fixture path.

**Root cause of every "missing scored rubric rule" report:** `cli.ts` wrote the
raw `--na` CLI arg into `provenance.notApplicable` instead of
`report.notApplicable`. It had no test because importing `cli.ts` ran `main()`
and called `process.exit()` — no entrypoint guard. Both fixed, with a test.

## How to work this codebase

- Run tests from the REPO ROOT (`npm test`). Running vitest from
  `orchestrator/` changes cwd and produced a false alarm about a broken waiver
  guard tonight. A test invocation is itself a measurement.
- For any rule, ask **what input would make this FAIL**, then produce it.
  Confirming the good case still passes proves nothing. This is now a hard rule
  in `CLAUDE.md` and rows G6/G7 in `docs/DONE-CHECKLIST.md`, bound to
  implementations and covered by tests.
- Never re-stamp a verdict. Re-stamping is not re-measuring.
- Open the screenshot. Reading a component and concluding what it renders is
  how a black hero shipped inside a light page.
