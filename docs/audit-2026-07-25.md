# Second audit — 10 further findings

Measured against `0c32583` (v6.0.0), after the ten findings in the first audit were fixed.
Every claim here was checked against the repo or the live site, not inferred.

## 1. `lg-runtime-parity` is still a declared blocker with no runtime check

> **CLOSED in v6.1.0.** `u-plat-runtime-parity` boots the app on the real Workers runtime and
> requests `/` plus every discovered health endpoint. Proven not vacuous: an app whose health
> endpoint returns 500 fails with exit 1.


`rules/loop-gate.md` says: "After build, boot the app on the real runtime (`wrangler pages
dev`) and curl a live backend endpoint plus the homepage; a non-200 or a runtime throw fails
the gate." Nothing in the gate does this. `u-plat-worker-runtime` is a static grep for
`process`, `Buffer`, node: imports and native deps.

A static grep cannot catch a Workers-incompatible transitive dependency, and the corpus calls
this "the single most repeated production failure in this environment". The e2e smoke does hit
a live endpoint, but only after deploy — the gate can pass a build that never boots.

**Fix:** add a `lg-runtime-parity` run rule that boots `wrangler pages dev` against the built
output, curls `/` and `/api/health`, and fails on non-200.

## 2. The dashboard is never gated

> **CLOSED in v6.1.0.** 24 recorded verdicts, `results/dashboard.json`, and its own CI
> reproduction job. Scores 100/100 across 45/45 at 83% coverage.


`results/` contains only `app-builder.json`. There is no `evidence/verdicts-dashboard.json`.
`build_feed.mjs --check` reports "1 result file(s)" while two apps ship to production.

Half the deployed surface has no measured score. The dashboard was deployed and axe-audited
this session (0 violations, both themes) but nothing recorded it or gated it.

**Fix:** record dashboard verdicts, produce `results/dashboard.json`, add it to CI's
provenance job.

## 3. 385 duplicated lines across the two shells, structurally invisible to the rule

> **CLOSED.** `cross_app_duplication.mjs` compares every app tree against every other,
> normalising identifiers first so a rename cannot defeat it, and runs in `gate_repo_ci.mjs`.
> It measures **805** duplicated lines (more than the 385 exact-match figure below, because
> normalisation also catches near-identical utilities like `useDrawerA11y` and `ThemeToggle`).
> The budget is a RATCHET set at the current total: the number cannot grow silently, and is
> meant to be lowered. Verified independently — logic with every identifier renamed is still
> detected, unrelated apps measure 0, and the exit code is 1 over budget and 0 under.


Measured, identical trimmed lines between `app-builder/src/components/shell/` and
`dashboard/src/components/shell/`:

| file | identical lines | of |
|---|---|---|
| styles | 137 | 211 / 209 |
| Footer | 82 | 140 / 131 |
| Header | 68 | 76 / 76 |
| NavLinks | 64 | 100 / 101 |
| MobileDrawer | 59 | 67 / 67 |
| constants | 8 | 11 / 11 |

`hyg-no-duplication` runs with cwd set to one app directory and walks only that app's `src`
and `functions`, so it cannot see across the two. The shell split improved each app's file
sizes and left the cross-app duplication exactly where it was. Its detector is also exact
8-line string matching, so renaming one identifier defeats it.

**Fix:** a repo-level duplication pass in `gate_repo_ci.mjs`, or extract a shared shell
package. The latter needs monorepo wiring both apps currently avoid.

## 4. `proc-full-local-suite` has no implementation at all

> **CLOSED — removed.** A rule waived on every single invocation is not a rule. CI running the
> full suite on every push, plus `verify_commit.mjs`, is the real enforcement.


Zero occurrences in `check.mjs` and zero in `gate.ts`. Method is `hook`, which is fail-closed,
so it fails on every run — and every real run passes `--na process`, which waives it. A
declared rule is therefore permanently waived rather than ever measured. This is the exact
"declared but unimplemented" pattern the rubric already fixed elsewhere, surviving inside the
waiver.

**Fix:** implement it (assert the local suite ran against the commit being gated) or remove it
from the rubric. A rule that is always waived is not a rule.

## 5. Two blockers are decided by one command, and nothing checks that command means anything

> **CLOSED.** `u-typing-no-any` now also asserts the app's eslint config genuinely sets
> `no-explicit-any` to `error`, so it and `u-conc-dead-code` have distinct evidence. Five tests.


```
{ ruleId: 'u-typing-no-any',   command: 'npx', args: ['eslint', '.', '--max-warnings', '0'] },
{ ruleId: 'u-conc-dead-code',  command: 'npx', args: ['eslint', '.', '--max-warnings', '0'] },
```

Two independent blockers, one invocation. They can never disagree, so the rubric reports two
measurements where one exists. Worse, neither verifies that the target app's eslint config
actually enables `no-explicit-any` or an unused-vars rule. An app shipping a permissive config
clears both blockers with an empty lint run. The scaffold does emit a config that enables them,
but nothing enforces that a hand-written app does.

**Fix:** assert the resolved eslint config enables the specific rules before trusting the exit
code, and give the two rules distinct evidence.

## 6. `--na` is reality-checked for exactly one lane

> **CLOSED.** `assertWaiversAreReal` checks every decidable waiver and reports all failures at
> once. A false `--na u-plat-runtime-parity` is now rejected with its reason. Nine tests.


`gateApp` refuses `--na ci` when `.github/workflows` exists. That is the only guard. The
`process` lane, and any individual rule id, can be waived with no check whatsoever. The waiver
decides the denominator, which makes it the widest lever on the score, and six of its seven
uses are undefended. This run waived `ci`, `process`, `proc-pr-title-ticket` and
`u-sec-timeouts`, and only the first was validated.

**Fix:** extend the reality check to every waiver — a waived rule must be one whose subject
genuinely does not exist.

## 7. The daily drift job never re-runs the gate

> **CLOSED.** `drift.yml` re-gates both apps daily with `fetch-depth: 0`, so verdict staleness
> finally has a cadence behind it.


`drift.yml` runs axe on four surface/theme combinations and the e2e smoke. It does not run the
gate, so verdict freshness is only ever evaluated when someone runs the gate by hand. The
mechanism added in v6.0.0 to stop stale evidence earning credit has no cadence behind it: a
verdict can go stale and stay stale indefinitely without anything noticing.

**Fix:** add the gate and `verify_results.mjs` to `drift.yml` (it needs `fetch-depth: 0`).

## 8. The e2e smoke covers exactly one flow

> **CLOSED.** The smoke now also verifies Saved and the four legal routes by role, and records
> them in its JSON summary.


`e2e_smoke.mjs` navigates to the base URL and drives chat → wizard → submit. Saved, the PRD
detail route and the template gallery have no end-to-end coverage, yet `fe-product-completeness`
is recorded from this single path and reads as a statement about the whole product.

**Fix:** either broaden the smoke or narrow what the verdict claims.

## 9. Test coverage is named in the corpus and measured by nothing

> **CLOSED — struck from the corpus.** A line implying a measurement nobody takes is worse than
> an honest gap. Add it back only with the tooling that enforces it.


`lg-role-deterministic-gate` lists "coverage" among what the deterministic gate runs. No
coverage tooling is configured in any package, and no rule scores it. `u-test-presence` is
satisfied by vitest exiting 0, which one trivial test achieves.

**Fix:** wire a coverage threshold, or drop the word from the corpus so it stops implying a
measurement that does not exist.

## 10. Orphaned evidence that looks authoritative

> **CLOSED.** The two stale-slug axe reports are deleted.


`evidence/axe/redanvil-dark.json` and `redanvil-light.json` are referenced by nothing — no
verdict, no script, no workflow. They are from an earlier slug and now sit beside the four live
reports with no way for a reader to tell which set is current. Evidence that nothing consumes
is indistinguishable from evidence that was quietly abandoned.

**Fix:** delete them, or have the drift job write them so they mean something.

## Not findings, but worth noting

`u-conc-no-padding` is weighted `major` and implemented as "3+ consecutive blank lines". The
rule text is about padding in general — try/except that only logs, docstrings restating the
signature, redundant intermediate variables. The check measures none of that. It is not wrong,
it is just far narrower than it reads.

## Attempted and reverted: sharing the React utilities (2026-07-25)

`useDrawerA11y.ts` is byte-identical in both apps (190 lines) and looked like the
obvious next ratchet step after `shellCss`. It was moved to
`design-system/hooks/`, re-exported from the old paths, and the duplication
total dropped 772 -> 646.

**It was reverted.** A module under `design-system/` resolves `react` from the
repo root while app code resolves the app's own copy, so the bundle carries two
React instances and every hook throws `Cannot read properties of null (reading
'useRef')` — in the browser, not only in tests. `resolve.dedupe: ['react',
'react-dom']` in both Vite configs did not fix it.

126 duplicated lines are not worth that risk. What this means for the remaining
duplication:

- CSS and other **React-free** modules can be shared today; that is why
  `shellCss.ts` works and took the total from 854 to 772.
- Anything importing React needs real monorepo wiring (a workspace package with
  `react` as a peer dependency, hoisted once) before it can move. That is the
  actual prerequisite for finishing finding #3, and it is a larger change than
  it looks from the line count.
